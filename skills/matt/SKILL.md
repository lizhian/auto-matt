# Matt 主流程控制器

主 agent 先读取已安装的 `ask-matt` 的 `SKILL.md`，结合用户目标、项目现状和已有决定判断场景。读取候选技能的实际指令后，选择足以完成请求的单个技能，或按依赖顺序组合多个技能。

运行中优先利用宿主事件记录起止时间。主 agent 和每个委派者记录自己实际使用的技能、子 agent 标识、任务和结果，回报时附上嵌套委派明细。

按需进入 **决策阶段 → 实施阶段（含收敛）→ 总结阶段**。用 `ask-matt` 发现候选技能，进入阶段后按该阶段的条件选用和调用技能。调用前明确本次要取得的结果和交回主 agent 的时机，再根据结果判断下一步。

每次发起代码审查（含实现技能的内置审查）时，调用方固定本轮范围并传给所有审查者。已提交部分给出基线和目标 SHA；另有工作区改动时，附上本次暂存、未暂存及未跟踪新文件的补丁，排除任务开始前已有的无关改动。纯工作区改动直接审查补丁。使用 `code-review` 时将这些材料作为实际 diff 输入，两轴审查均覆盖完整范围。

例如，使用 `diagnosing-bugs` 定位问题时，以复现证据和根因为本次诊断终点，在应用修复前交回主 agent。用户只要求定位时，交付诊断结果。用户要求修复时，若修法涉及尚未决定的行为或范围，先进入决策；预期已明确时，直接进入实施。

- 需要用户作取舍时，由主 agent 在主对话中执行[决策阶段](references/决策阶段.md)。
- 需要实现时，按[实施阶段](references/实施阶段.md)选择路线、确认计划或 Spec、实现并复核。
- 单独审查已有改动时，根据用户的问题选路。核对 Spec 完整性或项目规范时用 `code-review`，精简实现或测试时用[收敛标准](references/收敛标准.md)。两项都要求时共用同一份 diff，一次报告两类发现。仅在用户要求修改时动手。
- 交付需求实现结果或用户要求复盘时，按[总结阶段](references/总结阶段.md)汇报实际执行情况。
