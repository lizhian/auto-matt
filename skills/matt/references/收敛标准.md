# 收敛标准

规划时用以下标准明确本次改动的边界。复核时，对照已确认的需求、项目中的同类实现和实际 diff 判断。

- **合理性与最小范围**。改动能否解释为实现某项需求或保留既有行为所必需？指出可撤回的无关修改，以及能用更小范围完成的改动。
- **项目规范**。核对项目明文约定、模块边界和同类代码的实现习惯。提出调整时引用具体约定或现有用例。
- **过度设计与重复实现**。检查新增抽象、配置和扩展点是否有当前需求或调用方支撑。已有函数或模块可覆盖相同行为时，指出可复用的位置，并核对边界条件是否一致。
- **测试是否必要**。对照各用例能发现的故障，保留覆盖验收行为、关键边界和已知回归的测试。建议删除或合并时，指出哪个保留用例仍能捕获同一故障。例如，两条测试虽有相同预期输出，若分别验证公开接口和底层逻辑，仍要判断它们能否发现不同问题。

每项精简建议写明改动位置、可采取的操作和保留行为的依据。现有实现和测试都必要时，可直接通过。
