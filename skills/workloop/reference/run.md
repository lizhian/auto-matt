# 单票和多票运行手册

1. 按[票据模板](../templates/ticket.md)填写用户能判断的结果。单票直接使用票据，多票给每张票标出 Spec 和依赖。在项目现有任务目录或会话附件中保存一份运行记录，写明起始提交、集成分支和已确认的范围。
2. 主 agent 是运行记录的唯一写入者。每次状态变化更新相应行，把真实的子 agent 标识和证据路径记下来。只有依赖已经集成并通过验收的票才可派工。

| 票据 | 依赖 | 状态 | 工作区和基线 | 实现者和候选版本 | 审查者和结论 | 集成版本与证据 |
| --- | --- | --- | --- | --- | --- | --- |

3. 用[实现任务书](../templates/executor.md)创建子 agent。收到候选后，用[审查任务书](../templates/review.md)创建另一位子 agent。等待宿主的完成事件，检查报告与候选是否一致。修复后回到原审查者复核。
4. 主 agent 串行集成通过的候选。在集成版本上执行累计验收，保留各票对应的结果。遇到冲突或失败，记录实际版本与首次失败，保留工作区，修复后重验。
5. 单票在集成验证后交付。多票用审查任务书的终审部分，将起始版本、集成版本、总 diff、Spec 与各票结果交给新审查者。最终报告列出用户接受的例外和未验证项。复盘时把反复发生的问题及改进建议交给用户决定。
