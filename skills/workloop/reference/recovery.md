# 中断恢复

从运行记录找到最后一个有证据的状态。对照宿主的子 agent 状态、工作区的 Git 状态、实际提交和验收报告。遇到“已派工、无回报”先查原子 agent；合并结果不明时先检查候选是否已进入集成历史，避免重派或重复合并。

- 实现中断时优先续接原子 agent。会话丢失时保留工作区，在替代者的任务书中写清原候选、现有未提交改动和待验证项。
- 审查中断时核对审查目标。候选未变可续接；候选有实质修改则把新版本和差异交给审查者。
- 验证中断时检查命令的宿主状态、日志和回执。未完成的命令保留“结果未知”；确认进程结束、工作区仍对应预期版本后，用新的证据目录重跑需要的验证。
- 集成后发现缺陷时从当前集成版本开修复票，关联原票和失败证据。

交接记录写明票号、状态、工作区、最后确认的版本、原子 agent 标识、可信证据、未决问题和下一步。保留未集成改动，清理前核对工作区的归属和状态。
